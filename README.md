# ロボットは、だれの代わりになれる？／ただ君と共に（授業用アンケート）

2つのアンケートが入っています。URL の `?s=` で切り替わり、回答・結果・「回答済み」の状態はそれぞれ別に扱われます。

| アンケート | 回答ページ | 結果ページ |
|---|---|---|
| ロボットは、だれの代わりになれる？（4問） | `index.html` | `results.html` |
| 「ただ君と共にいたい」は存在しうるか（1問） | `index.html?s=tada` | `results.html?s=tada` |

先生モードは、それぞれの結果ページの URL に `&t=1`（ロボットの方は `?t=1`）をつけて開きます。

「コミュニケーションロボットは 友達／恋人／配偶者／親 の代わりになるか？」に、はい／いいえと理由で答えるアンケートです。
仕組みは「ジレンマ劇場」と同じで、HTML を GitHub Pages に置き、回答は Google スプレッドシート（Apps Script）に保存します。

- **回答ページ** `index.html`：ニックネームだけ入力 → 4問（はい／いいえ＋理由15文字以上）→ 確認 → 提出。提出直後に、その人の4つの理由が AI で分類され、コメントつきで表示されます。
- **結果ページ** `results.html`：提出した端末だけが見られます（`RESULTS_GATE`）。
  - 全体：関係ごとの「はい」の割合、はい派／いいえ派の理由の分類の割合、関係×はい／いいえ ごとの分類の割合の表、4問の答え方のパターン
  - 関係ごと（`?rel=friend` など）：はい／いいえの割合、それぞれの側の分類の割合、全員の理由カード（AIのコメントつき）。分類の行を押すとその理由だけにしぼれます。
- **分類**：合理的・機能的・感情的・教義的・規範的・経験的（＋判断できない）。主な分類1つと、含まれている分類を最大2つ。2つのアンケートで同じ分類を使うので、比べることもできます。AI には、どちらのアンケートの問い（「ただ君と共に」では前置きの文も）への答えかを毎回いっしょに渡しています。
- **「ただ君と共に」**：前置きの文と問いを表示し、「はい（存在しうる）／いいえ（存在しない）」と理由を書かせます。結果ページは全体タブなしで、はい／いいえの割合と、それぞれの理由の分類・理由カードを表示します。

## セットアップ

### 1. スプレッドシートと Apps Script
1. 新しい Google スプレッドシートを作り、「拡張機能 → Apps Script」を開く。
2. `gas/Code.gs` の中身を貼り付けて保存。
3. 「プロジェクトの設定 → スクリプト プロパティ」に追加：
   - `TEACHER_PASSWORD`：先生モードのパスワード
   - `AI_PROVIDER`：`anthropic` か `openai`
   - `ANTHROPIC_API_KEY`（または `OPENAI_API_KEY`）
   - 任意：`ANTHROPIC_MODEL`（既定 `claude-haiku-5-5`）／`OPENAI_MODEL`（既定 `gpt-4.1-mini`）
   - ジレンマ劇場と同じキーをそのまま使えます。
4. 関数 `setup` を一度実行して権限を承認（シート `responses` ができます）。`testClassify` を実行すると、API キーが動くかログで確認できます。
5. デプロイ → 新しいデプロイ → 種類「ウェブアプリ」、実行ユーザー「自分」、アクセス「全員」。`…/exec` の URL を控える。
   - `Code.gs` を直したときは「デプロイを管理 → 編集 → 新バージョン」で更新（URL は変わりません）。
   - Chrome で複数の Google アカウントにログインしていると URL に `/u/1/` などが入って動かないことがあります。シークレットウィンドウで確認してください。

### 2. GitHub Pages
1. `js/config.js` の `GAS_URL` に URL を貼る。
2. フォルダ一式（`gas/` は不要）をリポジトリに置き、Settings → Pages で `main` / `/ (root)` を公開。

`GAS_URL` が空のままだと**デモモード**です（ブラウザ内だけに保存、架空のサンプル回答22人分、先生パスワード `demo`、分類はキーワードによる簡易判定）。

## 授業での使い方
- 学生には `index.html` の URL を配るだけ。結果ページへは提出後のボタンから移れます。
- 先生は `results.html?t=1` を開いてパスワードを入れると、提出前でも結果が見られ、次の操作ができます：
  - **未分類の理由をAIで分類**：提出直後の自動分類が混雑で失敗したぶんを、まとめて分類
  - 各カードの **分類を直す**（先生の修正が優先して集計されます）／**学生から隠す**（不適切な書き込み用）
  - **CSVダウンロード**（全提出。`latest=1` が集計に使われている最新の提出）
- 同じ端末から出し直すと、最新の提出だけが集計されます。動作確認で使った端末は `index.html?reset=1`（`index.html?s=tada&reset=1`）で回答済みの状態を消せます。
- 2つのアンケートは同じシート `responses` に保存され、`survey` 列（robot／tada）で区別されます。前の版で作ったシートを使っている場合も、Code.gs を差し替えると列が自動で足され、それまでの行は robot として扱われます。

## 設定（`js/config.js`）
`MIN_REASON`（理由の最低文字数）、`RESULTS_GATE`（回答前は結果を見せない）、`AUTO_CLASSIFY`（提出直後に分類）、`AUTO_REFRESH_SEC`（結果ページの自動更新）。
問いの文や前置きは `js/common.js` の `SURVEYS` と `gas/Code.gs` の `SURVEYS`（両方そろえてください）、分類の定義や AI への指示は `gas/Code.gs` の `SYSTEM_PROMPT`、画面上の説明文は `js/common.js` の `LABELS` にあります（並びを揃えてください）。

## プライバシー
学籍番号は集めません。公開されるのはニックネームと理由、AIの分類とコメントだけです。端末の区別には、ブラウザ内で作るランダムなIDを使っています。
